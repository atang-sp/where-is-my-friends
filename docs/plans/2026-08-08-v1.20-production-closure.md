# v1.20 生产闭环与观察协议

## 范围与证据等级

本协议只为 v1.20 建立可执行的部署后观察和单变量决策流程，不授权部署、修改生产设置、
开启许可导入或写入生产数据。代码、测试、CI、部署和成熟生产样本是五种不同证据，不能互相
替代：

| 证据 | 含义 | 本文初始状态 |
| --- | --- | --- |
| 已实现 | 代码和测试已进入 v1.20 分支 | `IMPLEMENTED` |
| 已在开发环境验证 | 指定命令在完整 Discourse 开发环境实际通过 | 合并前填写验证记录；否则 `NOT_OBSERVED` |
| 已由 CI 验证 | minimum-core 与 latest-core 的必需任务实际通过 | PR check 通过后填写；否则 `NOT_OBSERVED` |
| 已部署生产 | 不可变插件版本已经按生产变更流程部署 | `NOT_OBSERVED` |
| 已取得成熟生产样本 | 对应 7/30/60/90 日观察窗已走完且满足样本门槛 | `NOT_OBSERVED` |

任何没有当前证据的字段统一写 `NOT_OBSERVED`。自动化测试通过只证明合同实现，不证明用户
建立了关系、完成了线下实践或产品有效。

## 连接指标合同

`connections` 的主对象是 `WhereIsMyFriendsPracticeInvitation`，并按 `native` 与
`legacy_reconfirmed` 分开。每个来源独立执行 aggregate privacy policy；不提供跨来源总计，
避免用总数减去已显示来源恢复被抑制的小组。

- 窗口快照：`created_at ∈ [since, as_of]`。历史 `as_of` 之后才发生的响应在快照中视为
  pending，不泄漏未来状态。
- 响应成熟 cohort：只有 `created_at <= as_of - 7.days` 的邀请进入分母；创建后七天内的
  accepted、declined、ignored 才是七日结果，晚响应单独计入安全的 late response。
- 接受定义：邀请状态为 accepted，且 `responded_at <= created_at + 7.days`。
- 双向会话代理：accepted 邀请的原发送者在接受后的七天内，于插件创建的同一个 PM 中发布
  `regular`、`post_number > 1`、未删除且未隐藏的回复。它只说明 PM 中出现往返。
- 未成熟邀请和未成熟 accepted 记录分别进入 `in_progress_invitations` 与
  `accepted_in_progress`，不进入失败分母。
- 参与者或任一细分小于统一隐私阈值时，整个相关 breakdown 返回 limited；不返回精确数量、
  比例或中位时间。

## 观察时间点

### T0：部署前

1. 记录上面的不可变版本、core SHA、设置、备份和回滚版本。
2. 保存 7/30/90 日聚合快照，确认普通用户和匿名用户不能访问管理员统计。
3. 确认许可导入关闭，个人动态分区继续满足受限、默认静音和单一自动组权限合同。
4. 记录 minimum-core、latest-core、RSpec、QUnit、lint、system tests 与完整 Playwright 的实际
   结果；缺失项写 `NOT_OBSERVED`，不得推断为通过。

### T+24h：安全和早期运行健康

- 检查持续 5xx、接口失败、后台任务异常、前端错误和日志异常。
- 验证匿名访问没有获得动态、连接聚合或其他会员数据。
- 检查 24 小时成熟 cohort；仍未走完窗口的数据只记 `in_progress`。
- 对比 T0 设置和分区权限，确认没有意外开启许可导入或改变其他功能开关。

### T+7d：最早七日 cohort

- 读取最早一批成熟的推荐、邀请、公开互动和动态回复 cohort。
- 对邀请记录 send → response → acceptance → sender follow-up；报告双向会话代理，不报告关系
  或线下成功。
- 同时记录 mature 与 in_progress，避免把后续获客当成失败。

### T+14d：完整推荐观察批次

- 覆盖连续七天获客后走完七日观察窗的完整推荐批次。
- 检查各 recommendation group 的曝光、打开、dismiss、24 小时公开回复和七日公开互动。
- 根据决策矩阵只选择一个主要产品变量进入下一轮。

### T+30d：动态与有限许可试点

- 个人动态只有达到作者、成熟动态、回复和发现样本门槛后才能作结论。
- 许可导入仍默认关闭。只有此前取得单独授权并完成最多五篇公开试点时，才评估五篇成熟
  样本；不足五篇必须 fail closed。

### T+60d：只处理动态样本不足

只有 T+30d 的个人动态样本未达到门槛时才延长到 T+60d。安全、匿名泄露或持续 5xx 不得
等待延长窗口。T+60d 仍不足时记录“样本不足”，不得宣称成功。

## 关键指标

### 同城入口

- `view → open`；
- `view → location saved`；
- `results with people`；
- profile、message、local-topic actions；
- 只使用成熟 cohort 的七日有效连接。

### 推荐

- topics、people、interests 和 dynamics 各分组的曝光、打开与 dismiss；
- 曝光后 24 小时公开回复；
- 曝光后七日公开互动；
- mature 与 in_progress 必须并列记录。

### 一对一邀请

- 窗口内 native send；
- 七日 response 和 acceptance；
- accepted → sender follow-up；
- reciprocal conversation proxy；
- `legacy_reconfirmed` 只在隐私允许时单独报告，不进入 native 转化率。

### 个人动态

- 至少 10 位非员工作者持续发布；
- 至少 30 条成熟动态后再判断七日回复；
- 成熟作者跨日再次发布率至少 30%；
- 七日真人回复率至少 40%；
- 首页动态打开率至少 10%；
- 成员卡综合打开率不得比 31.25% 基线低超过 5 个百分点；
- 样本不足时最多延长到 60 天，不得用小样本宣称成功。

### 许可导入

- 默认 `licensed_import_enabled=false`；
- 先完成三篇 dry-run 人工检查；
- 公开运行需要单独人工授权，且最多五篇；
- 五篇成熟后至少三篇在各自七日内获得真人回复；
- 最近 30 天真人原创内容供给不能下降；
- 30 日样本不足、回复率不达标、原创供给下降或其他异常均 fail closed。

## 决策矩阵

| 观察 | 下一轮唯一主要动作 |
| --- | --- |
| 首页曝光不足 | 只优化入口，不修改后续漏斗 |
| 曝光正常但打开率低 | 只优化推荐理由或排序 |
| 成员卡打开正常但邀请发送少 | 检查邀请入口和权限摩擦 |
| 邀请发送正常但接受率低 | 增强上下文和信任信息 |
| 接受率正常但发送者没有后续回复 | 优化 PM handoff |
| 动态作者不足 | 缩小入口，不增加功能 |
| 动态供给足但回复低 | 优化参与提示和分发 |
| 隐私、安全、匿名访问异常或持续 5xx | 立即回滚 |

每轮只能选择一个主要产品变量，不同时修改多个漏斗环节。没有达到成熟样本门槛时只能记录
`NOT_OBSERVED` 或“样本不足”，不能用趋势替代结论。

## 回滚

1. 安全、匿名泄露、权限绕过或持续 5xx：立即关闭受影响的最窄子功能；若无法隔离，关闭
   `where_is_my_friends_enabled`。
2. 个人动态按成员卡入口、首页入口、动态主开关的顺序收缩，不删除 Topic/Post 或自定义字段。
3. 许可导入异常只关闭 `licensed_import_enabled`；不删除来源记录、预览、主题或审计字段。
4. 代码回滚使用 T0 记录的不可变插件版本和生产部署流程；不移动已发布 tag，不删除迁移列或
   兼容表。
5. 回滚后重新执行 HTTP、匿名访问、后台任务、日志、数据库迁移状态和聚合隐私检查，并记录
   操作者、时间、原因和结果。
